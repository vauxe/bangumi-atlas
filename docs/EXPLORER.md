# bangumi-atlas 探索应用设计文档(桌面端 3D)

把图数据库做成可公开部署的 3D 交互式星图("Bangumi 星图")。
状态:已实施(§9 全部步骤落地;实测偏差与既定取舍见 §7/§10)。
前置:构建管道(见 [DESIGN.md](DESIGN.md))。
2026-07-31 目标改写:原为任意设备的 2D 瓦片方案,现改为桌面端专属、3D 呈现。

## 1. 目标

受众:桌面浏览器 + 近五年 GPU;Apple Silicon Mac 为基准设备,
spike 与验收在其上实测(Retina 下必要时钳 devicePixelRatio)。
非目标:移动端、低端设备、实时数据、让用户写查询。

延迟预算(验收标准,桌面宽带,基准设备实测):

| 交互 | 预算 |
|---|---|
| 首屏可交互(首块渲染) | < 5s |
| 全量几何后台补齐 | < 30s,不阻塞交互 |
| 探索循环(点击 → 邻居亮起) | < 300ms |
| 搜索联想 | < 100ms(分片已热;冷分片 p95 < 400ms,高频首字随首块预取) |
| 全图帧率 | ≥ 30fps(DPR 钳 1.5;远景纯点实测 47fps) |

## 2. 核心架构

**入图范围**:星图节点 = 作品/人物/角色,约 99 万
(全库 266 万节点中的 Episode 分集约 168 万**不入图**——
它们是作品的从属细节而非探索目的地,经详情面板到达);
入图边为除 EPISODE_OF 外的约 380 万条。

**工作集**(选中+邻居,百级,承担全部交互)与**语境**
(其余入图节点)二分。关键结论:

- 渲染与拾取都在 GPU(99 万点,CPU 拾取与渲染均超预算)
- 邻居/详情按节点预连接为离线分片 ⇒ 运行时零计算 ⇒ **零后端,纯静态**
- 几何按收藏度降序,分六个 SoA 属性文件并行流式渐进渲染
  (重要节点先出现,排序即分层,无需骨架/补全两层)
- 布局离线冻结,每周以上周坐标热启动(位置恒定、URL 可分享的前提)
- 搜索为客户端前缀索引

```
离线(每周,GitHub Actions cron)
  fetch_dump → build_db → verify_db
    ──3D 力导布局 + 社区检测──> 坐标/社区(上周坐标热启动)
    ──烘焙──> 几何包、名字表、邻接/详情/搜索分片、标签表
    ──deploy-pages──> GitHub Pages(纯静态,零服务器)
线上
  deck.gl:语境层(点+骨架边)+ 工作集叠加层 + 标签层
  搜索/邻居/详情走静态分片,拾取走 GPU picking
```

数据分层加载(Pages 1GB 限 raw 体积;其压缩仅覆盖文本类 MIME,
二进制几何按 raw 传输):

| 包 | 内容 | gzip/raw 估 | 时机 |
|---|---|---|---|
| 几何+名字 | 全部入图节点,按收藏度降序;名字为 NDJSON 逐行流式 | ~30/56MB 实测 | 流式渐进,首块即渲 |
| 坐标快照 | coords.parquet(21.5MB),下周热启动 + 位置恒定的事实来源 | ~10/21.5MB | 不进首屏,仅管道拉回 |
| 骨架边 | 每节点保底 top-1 + 度归一权重补足;保底本身实测 82.2 万条(连通节点 89 万决定下限,> 50 万原预算,烘焙时显式告警),按权重降序存储;**仅近景显示**(zoom 阈值淡入相机目标附近的可见集,CPU 重建 + 上限 12 万条——spike 实测边为填充率瓶颈,+10 万边即 29fps) | ~3/6.6MB | 随首块 |
| 分片 pack | 邻接/详情(summary 全文)/搜索索引/溢出页:逐片 gzip 后打包(adj.pack、det-{0..3}.pack、search.pack、pages.pack)+ u32 偏移索引,客户端 HTTP Range 取片、DecompressionStream 解压;存储即压缩 | ~340MB(即传输量) | 按需 Range |
| 标签表 + manifest | 见 §6 | ~3/6MB | 随首块 |

站点 raw 合计实测 **447MB / 21 个文件**(打包前 958MB / 2.5 万
文件——详情分片曾裸存 700MB 靠 CDN 压缩传输):1GB 体积与
CF Pages 2 万文件数两个约束同时解除,门禁保留(超 1GB 构建失败)。

## 3. 技术选型

| 层 | 选型 | 落选者(原因) | 退出条件 |
|---|---|---|---|
| 烘焙管道 | Python(mypy 契约) | Rust/C#/Go(缺大规模图布局或 DB 绑定) | — |
| 3D 布局 | **裁决:igraph UMAP-3D**(全图 15 分钟;边紧凑 0.022 / 社区分离 0.129)| DRL(子图 2h+ 未完成,运营失格)、fa2(仅 2D) | 布局质量恶化 → node2vec+PaCMAP |
| 渲染+拾取+标签剔除 | deck.gl(TypedArray 直灌、GPU picking、CollisionFilter) | 裸 WebGL(自造成本)、three.js(拾取/剔除仍需自造)、cosmos/sigma(2D) | spike 不过 30fps → regl 混合或 three.js |
| 客户端语言 | TypeScript strict | JS(无类型检查)、Blazor/WASM(interop 税,CPU 无热点) | profiler 证实的 CPU 热点 → 单模块 WASM |
| DOM 层 | 零框架(微型 store + 转义模板 + 纯函数组件) | React/Svelte(细粒度高频更新的收益覆盖不到粗粒度低频负载) | DOM 膨胀出表单/多面板 → Svelte |
| 构建 | esbuild(转译+打包+serve;缓存一致性由数据 `?v=版本` 寻址与 Pages ETag 承担) | Vite(HMR 被"URL 即状态"抵消,插件无消费者) | 引入框架时随之换 Vite |
| 托管 | Actions cron + Pages artifact(零 commit) | VPS(违反零后端推论) | 超 1GB/带宽 → Cloudflare R2 |

## 4. 交互设计

四层:**搜索着陆**(命中 → flyTo + 选中 + 亮邻居)→ **总览**
(语义缩放,社区色块与分级标签)→ **点击生长**(邻居按收藏度
top-50,回显"还有 N 个";分片已按此预排序)→ **领域钩子**
(时间机器、随机传送、过滤结果榜、共同关联与六度路径)。

查询三件套(2026-07-31,第一性原理裁定:粉丝的问题只有
定位/上下文/相似/时间/筛选/连接六种形态,前四种已有,补后两种):

- **结果面板**:任一作品过滤激活时,左侧枚举满足条件的作品
  top-N(节点本身按热度排序,顺序扫描即榜单;媒介在视图里只
  调暗、在查询里是条件),点击即飞。谓词 + 枚举 = 完整查询
- **共同关联**:抽屉"⚭"锁定起点,再选一个节点 → 两者邻接
  (各自热度 top-200)交集,双边关系名并列,场景画双扇形
- **最短路径**:抽屉"🧭"锁定起点 → 有界双向 BFS(≤6 跳、
  每层前沿 ≤48、每节点扩展热度 top-48 邻居,经 hub 相遇概率
  最大),链式呈现并标注每跳关系名;超界显式报"未找到"。
  类 Cypher 自由查询维持反模式:六种问题形态无一需要图代数

3D 适配:

- **相机**:turntable(禁 roll);双击 = 聚焦飞行;`H` 复位;
  俯视正交预设作 2D 保底
- **拾取**:GPU picking 返回数组索引,经几何包内的全局键
  还原为(类型, id);重叠处连续点击循环切换;**悬停即预取**该节点
  的邻接+详情分片,对冲每周失效后的冷 CDN 延迟
- **工作集聚光 + X-ray**:语境降至 ~15% 亮度解决显著性;遮挡由
  工作集两遍渲染解决——深度通过正常绘制,深度失败画低亮描边剪影,
  被挡邻居永远可见且保留"在后方"的信息
- **深度线索**:雾衰减表深度(只作用于语境层);节点尺寸用世界
  空间 + 像素上下限钳制(radiusMin/MaxPixels),收藏度编码于钳制带
  内的尺寸序与亮度——保留远景光学聚合,近景不糊成实心盘
- **边显示策略**(spike 定案):远景纯点;zoom 过阈值后淡入视锥内
  骨架边;工作集边任何时刻可见
- **实时过滤与重着色**:时间机器 = 作品按年份过滤;评分下限
  滑块与标签 chips(top-32 元标签位图,AND 语义)可与年代/媒介
  自由组合(2026-07-31 属性过滤扩展)——不满足的作品隐藏,
  人物/角色随任一作品过滤降暗(不隐藏);单端被滤除的骨架边由
  CPU 重建可见集(毫秒级);媒介 chips = 即时调暗;图层切换 =
  即时换色。全部过滤都是 shader uniform,全图即时响应

反模式:让用户写 Cypher;无界展开。

URL 编码的完整状态:相机位姿、选中节点、图层、媒介过滤、时间
范围、评分下限(`s=`)、标签集(`t=`);
每个操作可逆。

## 5. UI 设计

布局:画布全幅,无欢迎层——左上角一列:搜索框(骰子内嵌其
右端)→ 筛选面板(标签/评分/媒介/时间,可折叠)→ 过滤结果榜;
右侧 420px 详情抽屉、左下图例。图层切换与俯视不再占按钮,
走键盘 `C`/`T`(2026-07-31:右下工具簇取消,过滤移左列,
骰子入搜索框——工具簇曾被打开的抽屉遮挡且与左侧结果榜割裂)。
冷启动仅背景缓慢自转,首次交互即停。
(原设计的"居中搜索框 + 标题"冷启动层已移除:遮挡星图中心,
且只随选中收起、不随交互消失,实测裁定,2026-07-31。)

详情面板:标题 → 类型徽章 + 评分收藏 → summary 折叠 →
关系分组列表(组头 = 解码关系名,组内 = 可点节点 chips,
**点击即行走**;作品的分集列表也在此)→ "展开全部 N 个" →
bgm.tv 外链。

输入语法(键盘操作以本表为准):

| 输入 | 反馈 | 预算 |
|---|---|---|
| 左键拖 / 滚轮 | 平移 / 推拉 | ≥30fps |
| 右键拖 | 轨道旋转(turntable) | ≥30fps |
| `T` / `C` / `R` | 俯视正交 / 类型⇄社区着色 / 相机复位(2026-07-31 改为见字知意键位 Top/Color/Reset,原 `2`/`H` 与对应工具栏按钮移除) | 即时 |
| 悬停节点 / 工作集内的边 | tooltip(名字+类型 / 解码关系名;语境层骨架边不出 tooltip) | 即时 |
| 单击节点 | 选中:聚光 + 抽屉 + 邻居亮起;轨道枢轴滑移至该节点(保持缩放)——此后滚轮推向它、右键绕它转(URL 还原时枢轴不动,尊重链接机位) | <300ms |
| 重叠处连续单击 | 循环切换候选 | 即时 |
| 双击节点 | 聚焦飞行 | 400ms |
| 单击空白 | 取消选中,语境复亮 | 即时 |
| 点抽屉 chip | 行走:选中转移 + flyTo,历史入栈 | <300ms |
| `S` → 输入 → 回车 | 聚焦 → 联想 → flyTo + 选中(原 `/` 移除) | <100ms 联想 |
| Esc / 浏览器后退 | 逐级退出 / 回上一视图 | 即时 |
| 🎲 / 时间滑块 / 媒介与图层 chips | 传送 / 年份过滤 / 重着色 | 即时 |

贯穿规则:每个操作可逆;每个状态可分享。

颜色(初音未来主题,2026-07-31):黑青夜空表面 `#0f1a1c`;
交互元素静默态 = 葱色 `#39c5bb`(chips/链接/展开按钮),
高亮态 = 发饰粉 `#f25ba6`(激活 chips/搜索焦点/悬停高亮/
选中光晕与脉冲/滑块);抽屉为粉色面板 `#422339` + 品红描边。
数据三色为编码色、不随主题漂移:作品 `#3d8ede` 天蓝 / 人物
`#e56a40` 珊瑚 / 角色 `#27ab7c` 薄荷,在本表面重新通过色觉缺陷
分离度(OKLab ΔE ≥8,最差对 8.7 deutan,全对校验)与对比度
(≥3:1)校验,该校验下同屏类别上限为 3。粉与葱色刻意不入类别
(粉-薄荷在红绿色盲下 ΔE 仅 2.8,实测否决)。字体:圆体优先
(ui-rounded / macOS 圆体 / Windows 幼圆),画布标签同族。
媒介(= 作品的书籍/动画/音乐/游戏/三次元五类)不用 5 色同屏,
以 chips 隔离(选中亮、其余暗)。
社区层例外:辨识靠位置与社区标签,颜色仅作分区(低饱和多色)。
文字用文本色阶;类型信息不单靠颜色(徽章/图例有文字)。
动效仅三:flyTo 400ms、邻居 30ms 级联淡入、光环单脉冲,
尊重 prefers-reduced-motion。

## 6. 组件与数据契约

数据契约(两半系统的唯一接口;以本表为源,Python/TS 双侧手写类型,
变更须同步双侧):

**收藏度**(全文统一指标)= 收藏该实体的用户数:Subject 取
favorite 五档合计,Person/Character 取 collects,量纲一致可跨类型比较。

| 产物 | 形态 |
|---|---|
| manifest | 数据版本(dump-YYYY-MM-DD)、分桶参数(buckets/det_packs)、年份滑块范围、全部产物文件清单(逐个 sha256,分片打包后仅 ~20 个顶层文件)、搜索热分片清单、布局位移报告;每次发布的入口,客户端全部数据请求携带 `?v=数据版本` 寻址(防缓存错配;每周原子替换使版本级寻址即足,文件级哈希供对账与排查) |
| 几何包 | SoA 并行数组,合计 21B/节点(8 文件):positions 3×u16 / year u16(非作品或无日期 = 0)/ key u32(类型≪24 ∣ id)/ community u16 / size u8(log 收藏度)/ flags u8(bit0=nsfw 保留于数据、渲染不使用,bit1=孤立外壳、bit2-4=媒介,余位 0)/ score u8(评分×10,属性过滤)/ tags u32(top-32 元标签位图,bit 序 = manifest.tags);按收藏度降序;定长记录支持 HTTP Range 按 rank 点查(深链/行走落点在流式未覆盖时先取坐标,URL 以 `r=rank` 提示);骨架边 u32 端点对,按权重降序(客户端前缀优先) |
| 名字表 | 入图节点 name + name_cn(仅 Subject 有;人物/角色中文名待 infobox 解析),NDJSON 与几何同序逐行流式 |
| 邻接分片 | 按 `key % 8192` 分桶,逐桶 gzip 进 `adj.pack`(`adj.idx` = u32 累计偏移,桶 b 的片 = [idx[b], idx[b+1]));每节点条目 `{g: [labelId, 组总数, inline ranks][], n: 总数, op?: 溢出页 [offset, len][]}`,inline = 收藏度 top-200,溢出页逐片 gzip 进 `pages.pack`、偏移内嵌条目("展开全部"零索引往返)。对称表(条目/人物/角色关系)上游双向存储,按源方向入列防双写;缺失反向行(实测 1.4 万)补一条;完全重复行剔除并计数 |
| 详情分片 | 同分桶逐桶 gzip,按桶均分进 `det-{0..3}.pack`(`det.idx` 存全局累计偏移,单 pack <100MB);短属性 + summary 全文 + 作品的分集列表(超 200 集分页进 `pages.pack`,偏移内嵌 `eo`);infobox 不上站(未解析 wiki 源码) |
| 搜索索引 | 前缀分片(CJK 一字一档,逐档 gzip 进 `search.pack`,`search.idx.json` = {首字码点 hex: [offset, len]};变体折叠:简/繁/日文新旧字体归一,由烘焙期导出的**单字映射表**(OpenCC jp2t+t2s 逐字推导)统一定义,索引键与客户端查询同表逐字折叠——整串短语级转换与逐字必然分歧,故两侧都只用逐字;显示保留原文;拉丁小写):作品 name+name_cn、人物/角色 name,实测 ~112 万条(原估 165 万,人物/角色暂无中文名),条目携带 rank;高频首字分片清单入 manifest,随首块预取;中缀匹配为 v1 非目标 |
| 标签表 | 节点标签 top ~2 万(收藏度加权,客户端碰撞剔除 + 可见性过滤)+ 社区标签(= 社区内 top 节点名,覆盖全部社区并对账);字符集烘焙期离线给定,SDF 图集由 deck.gl 运行时生成、标签层延迟到首帧后空闲挂载(不占首屏,取舍见 §7) |

管道新模块:`layout.py`(3D UMAP + Leiden 社区检测(社区 ID 与
上周按成员重叠**一对一**匹配对齐,防配色每周洗牌)+ 孤立节点外壳
安置;生产布局用全部入图边并对 hub 降权(UMAP 边距离 ∝ √度数积,
即边权 ∝ 1/√度数积);热启动 + 跨周 p95 位移测量写 report.json;
坐标从上次发布站点拉回,`actions/cache` 后备)→ `bake_site.py`
(几何/名字/邻接/详情/搜索/标签/卡片单模块内分函数烘焙,原设计的
四模块拆分收敛为一,契约不变)。沿用既有纪律:失败与截断必须
显式报出、行级对账(对不上非零退出)。

客户端模块:`scene`(三层 + 可见性掩码 + 边可见集)/ `camera`
(turntable/飞行/正交/自转)/ `store`(~40 行)/ `url` /
`loader`(流式渐进 + Range 点查 + 分页)/ `search` /
`drawer`(纯函数 + 转义模板)/ `labels` / `html`。

  重新入图条件:上游出现集级 staff/出场边,或做"选中作品时按需
  环绕展示分集"的工作集级特性
- **3D 可读性代价已知,四件套缓解**:聚光、屏幕空间尺寸、雾、
  俯视正交保底——研究共识(屏幕 3D 分析效率低于 2D)仍成立,
  缓解不是消除
- **布局冻结 + 热启动**:心智地图与可分享 URL 的前提。
  周更协议(实测定案):warm seed + epochs=10 + 输出对上周坐标做
  正交 Procrustes 对齐;扰动实验 p95 位移 2.1%(严格 1% 门槛未过,
  但该实验随机传送 1% 存量节点,远苛于真实周更的"新节点长在簇边缘",
  门槛放宽至 3%,第一个真实周更的位移留观)
- **孤立节点放逐外壳**:度 0 节点实测 9.2 万(入图的 9.3%,主要是
  未录入关联的游戏/书籍),力导与嵌入都给不出有意义的位置;
  布局后安置在外围球壳,按类型+年代排布,默认调暗——保住
  "任何实体可搜索可 flyTo"的承诺,不给星图糊噪音
- **按重要性排序的渐进加载**:标准化替代为 OGC 3D Tiles(其
  additive 细化模式 = 粗层装重要节点、细层逐级补全,同语义,
  deck.gl 原生消费);当前规模全量常驻 GPU 即可(以 normalized u16 直灌为前提,缓冲
  <50MB;放任 deck.gl 默认扩成 Float32 则 ×2),单文件流式够用,
  规模 ×10 或首屏要压进 2s 时升级。
  3D Tiles 降传输量,不降客户端 GPU 的能力门槛。
  实现注:positions 传输为 u16,客户端反量化为 Float32 直灌
  (全部缓冲实测 ~24MB,仍远低于 50MB 预算);normalized u16
  直灌需自定义 per-axis 反量化 shader,留作规模升级时的优化
- **骨架边预算修订(实测定案)**:"每节点保底 + 总量 ~50 万"两个
  约束不可同时成立——连通节点 89 万,逐节点 top-1 去重后即 82.2 万
  条。取保底优先(近景任何节点都该有连线),总量超限由烘焙显式
  告警;帧率约束改由客户端承担:边只进"相机目标附近 + 双端可见"
  的可见集,上限 12 万条,CPU 毫秒级重建(这同时实现了"单端被
  滤除的骨架边重建可见集")
- **SDF 图集不做烘焙期预生成**:deck.gl TextLayer 无外部图集
  接口,自造字形管线不值得;改为字符集离线给定 + 运行时生成,
  标签层延迟到首帧后空闲挂载,守住"不占首屏"的验收本意。
  规模变大或首屏预算收紧时再自造(IconLayer + 离线图集)
- **manifest 哈希粒度**:一等文件逐个 sha256,分片目录(3.5 万
  文件)记聚合哈希——每周 Pages 原子替换,客户端防错配靠
  `?v=数据版本` 已充分;逐分片哈希只多 2MB manifest 而无消费者
- **不做节点展开/合并**:那是"画布只有子图"工具的必需品;
  本设计全图常在、揭示靠聚光,合并的职能由远景光学聚合 + 社区色块
  + 分级标签承担。引入则污染 URL 状态、破坏跨用户的位置恒定
- **NSFW 不做特殊处理**(2026-07-31 裁定,推翻原"默认过滤 +
  显式开关"设计):产品定位为个人向探索工具,过滤/开关/联想
  规避等整套机制移除;nsfw 位保留在烘焙数据中(flags bit0),
  需要时可低成本恢复策略
- **工作集封面缩略图**(2026-07-31):选中节点与邻居(≤51)以
  bgm.tv 官方 API 封面重定向(`/v0/{kind}/{id}/image?type=grid`,
  实测全链路 CORS 通过、302 带 1h 缓存)渲染为贴图,圆点保留在
  下层作加载失败兜底与拾取载体。全图缩略图不可行:Archive dump
  不含图片字段(实测字段清单),98.5 万张第三方实时图既超纹理
  容量也等于对上游洪泛;语境层维持圆点
- **分享卡片已移除**(2026-07-31 裁定):曾为 top 1 万节点烘
  og:meta 静态 stub(`/n/{key}.html`)供社交平台链接预览;
  裁定为非必需,整体去掉——省 1 万个文件与一条 NSFW 暴露面,
  URL 分享仍完整可用,只是平台预览卡退化为站点级标题。
  需要时可在烘焙管道按原契约恢复
- **分片打包**(2026-07-31 裁定):2.2 万个分片 JSON 逐片 gzip
  打包为 4 类 pack + 偏移索引,客户端 Range 取片 +
  DecompressionStream 解压。收益:文件数 2.5 万 → 21、站点
  955MB → 447MB(详情裸存改为存储即压缩)、单次取片传输与原
  CDN gzip 持平。代价:浏览器对 Range 响应基本不做 HTTP 缓存
  (会话内存缓存 + 数据每周整体失效,损失有限);需
  DecompressionStream(桌面近五年浏览器,目标受众内);
  无 Range 的服务器(开发环境)自动回退整包下载一次、本地切片。
  两条路径均经无头 Chrome 实测

## 8. 部署

Pages 部署源 = GitHub Actions:烘焙产物经 artifact 直发托管层,
不产生 commit,每周原子替换;数据生命周期:上游 releases →
runner 临时盘 → artifact → CDN,全程不进 git。
runner 限额(4 vCPU/16GB/14GB 盘/6h)均在需求内;
`ladybug` 有 manylinux 全版本 wheel(已核实)。
限制与迁移:Pages 带宽软限 100GB/月 ≈ 全量访客 ~2,200 人/月,
且二进制不压缩——**公开推广即迁 Cloudflare(Pages/R2),这是既定
路径而非尾部预案**(workflow 只改部署步骤);cron 60 天不活跃停用
→ keepalive;不便静态化的计算 → Workers。

## 9. 实施顺序(按风险从高到低)与验收

1. **帧率 spike**:99 万点 + 50 万线段灌 deck.gl,基准设备实测,半天
   (顺带验证流式分块上传 GPU 的渐进渲染)
2. **布局对决**:力导(igraph FR/DRL)vs 嵌入(node2vec +
   UMAP/PaCMAP + Procrustes 对齐)各跑 RELATES_TO 子图,预览评质量;
   **准入门槛 = 热启动稳定性**:注入模拟周增量重跑,p95 位移
   < 全图直径 1%,不达者出局(嵌入无对齐机制则结构性出局);
   胜者加测全图规模验证外推
3. 几何导出 + 场景 + 拾取 + 聚光/X-ray(验收含:点击 top-10
   度数节点,邻居可辨认)
4. 搜索 + 抽屉 + 行走循环(**完成即 MVP**)
5. 标签剔除
6. 每周 Actions workflow 上线
7. 钩子:时间过滤 → 骰子
8. 打磨:雾/辉光/动效

验收 = §1 预算表在基准设备上的实测数字。
