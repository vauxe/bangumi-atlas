# GitHub Pages 静态结构化查询设计

本文定义 Bangumi 星图的查询产品、交互与实现边界。字段、类型和能力以
[`scripts/query-contract.json`](../scripts/query-contract.json) 为准；物理文件以同一 Release 的
`manifest.json` 为准。查询功能只有在第 7 节门禁全部通过后才进入可部署产物。

## 1. 产品模型

用户不是在编写程序，而是在逐步回答四类问题：

| 答案形态 | 用户任务 | 示例 |
|---|---|---|
| 列表 | 定位并缩小一组实体 | 查找评分不低于 8 的机器人动画 |
| 统计 | 分析当前集合 | 按年份统计动画数量 |
| 集合比较 | 找共同项或差异 | 宫崎骏与久石让共同关联的作品 |
| 路径 | 解释两个实体如何相连 | 宫崎骏到新海诚的最短关系路径 |

字段、正文、关系、布尔条件、返回列和排序都是查询的组成部分，不是独立产品模式。四种答案共享同一套领域
词汇、查询动作和执行器。

查询只有一个用户入口：**统一查询栏（Tokenized Omnibox）**。默认的 `[查找全部]` 同时在作品、人物和角色中给出
名称建议，不要求用户先选类型；分集可通过查询头显式选择。添加条件或答案 Token，或查看完整结果时，
同一个查询栏继续表达字段、正文、关系、统计、比较和路径。
用户不需要先判断自己是在“搜索”还是“详细查询”。名称建议使用轻量索引，完整查询在 Worker 中执行，但两者
读取同一份 `QueryDraft`，不形成两套输入或筛选状态。

查询栏不是筛选表单、数据管道、源码或富文本编辑器。用户通过输入、补全、Token 和结果操作修改同一份查询，
不需要学习 SQL、Cypher、字段键或枚举码。

设计遵循以下原则：

1. **一个入口**：名称定位和完整查询共用一个查询栏，复杂度随用户动作逐步显现。
2. **一种含义**：界面、恢复和执行都来自同一份类型化查询状态。
3. **渐进表达**：先输入名称，再按需增加条件、关系、统计、比较或路径。
4. **领域语言**：只显示作品、导演、评分等用户概念，不显示内部键和值码。
5. **上下文约束**：补全只提供当前位置合法的选择，并优先展示与当前查询有关的内容。
6. **结果可操作**：结果既回答问题，也能成为下一步查询输入。
7. **静态可取消**：完整查询在浏览器 Worker 中执行，没有隐藏配额，用户可随时停止。

## 2. 交互模型

### 2.1 统一查询栏与答案工作区

统一查询栏默认以单行紧凑态位于画布左上方，普通文字的名称建议浮在下方。用户添加结构化条件、选择“查看全部
匹配”或创建统计、比较、路径后，精确答案在查询栏下方的窄浮层中展开；桌面端延伸至视口底部，Canvas 在右侧
始终可见且可交互。
关闭答案只收起浮层，不清空文字、Token、图上高亮或撤销历史；查询栏不复制到详情抽屉。

```text
定位
┌ [查找全部]  机器人▏                                  ＋  ┐
└───────────────────────────────────────────────────────────┘
  机器人总动员 · 作品
  机器人 · 角色
  查看全部匹配

完整查询
┌ [查找作品] [评分 ≥ 8] [导演是 宫崎骏]  机器人▏      ＋  ┐
└───────────────────────────────────────────────────────────┘
┌──────────────────────────────┐       ·  ◉  ·   Canvas
│ 12,438 个结果  图上 50 个当前结果 │     ◉    ·
│ 答案                         │  ·       ◉
└──────────────────────────────┘
```

补全面板浮在查询栏下方，不挤压答案。查询栏超出宽度时才按完整 Token 边界换行，可见的末尾输入至少保留可用宽度；
答案浮层的位置和尺寸稳定，编辑、加载和局部错误不卸载上一次有效答案。空状态只提供简短提示和少量上下文示例，
选择示例后直接生成普通查询，不建立模板系统。

### 2.2 语义查询句

已提交的语义按“意图与范围 → 条件与关系 → 答案 → 排序与显式边界”排列在前。接受名称条件的实体列表和统计
将当前名称文字放在末尾原生输入中；全局正文命中、比较和路径不接受名称条件，不显示该输入：

```text
[查找作品]  [评分 ≥ 8]  [导演是 宫崎骏]  [按评分降序]  机器人▏

[统计作品]  [类型是动画]  [年份 2000–2020]  [按年份计算作品数]  ▏

[查找正文]  [所有正文与关系备注]  [正文含“时间旅行”]  ＋

[比较共同关联]  [宫崎骏]  [久石让]  ＋

[最短路径]  [宫崎骏]  [新海诚]  [最多 6 跳]  [最多 10 条]  ＋
```

方括号表示一个可聚焦的语义 Token，不规定最终视觉必须是胶囊。紧密相关的意图和范围合并为一个查询头 Token，
避免把自然短语拆成碎片。列表名称保留为末尾原生输入；正文条件显式显示为 `[正文含“时间旅行”]`。每个
Token 显示完整含义，内部保存稳定键、稳定引用和类型化值。

默认的 `[查找全部]` 表示作品、人物和角色。名称建议与“查看全部匹配”必须使用这一范围。
当用户选择只对部分实体有意义的字段、关系或统计动作时，候选项显示目标类型；选择后的同一 `QueryAction`
将范围收窄到该类型，并立即改写查询头。不能在执行层暗中过滤不兼容的类型。查询头只允许扩大到与现有片段全部兼容的范围；
其他范围保持不可选并说明冲突片段，不静默删除条件。撤销收窄动作时恢复之前的完整查询。

列表状态中的末尾文字不是“尚未提交的草稿”，而是可立即执行的名称条件。因此
`[查找作品] [评分 ≥ 8] 机器人` 表示“作品，并且评分不低于 8，并且名称包含机器人”。增加、修改或删除 Token
不能清空、提交或改写这段文字；只有用户直接编辑文字时才改变名称条件。

意图和范围也是可编辑的语义片段。列表切换为统计时保留类型兼容的名称、字段和关系条件；集合比较和路径通常
由补全或结果动作创建，并明确替换不再适用的列表片段。

一个条件是一个 Token，例如 `[评分 ≥ 8]`，而不是 `[评分] [大于等于] [8]` 三个控件。点击 Token 中可见的
字段、运算符或值，补全面板直接进入对应步骤。普通条件保留创建顺序；多列排序的优先级在一个排序 Token 内
调整。相邻条件默认表示“并且”；“任一”、排除和混合逻辑用完整、可读的组 Token 表达。

### 2.3 Token 与文本共存

接受名称条件的实体列表和统计从左到右只有三类布局单元：查询头 Token、已提交的条件/答案 Token，以及由末尾
文本输入和“添加”按钮组成的输入组。Token 是离散语义，文本是需要逐字编辑的连续语义；两者共同投影自同一份
`QueryDraft`，不互相转换，也不存在第二个“手写查询”。

全局正文命中、比较和路径没有名称条件，因此隐藏同一个末尾输入，只显示 Token 与“添加”。输入 DOM 不重建，也不被临时改作
正文、端点或全局搜索输入；这些值只通过对应 Token 编辑。切换答案形态造成的语义替换是一个可撤销的 `QueryAction`。

- 点击 Token 正文打开锚定编辑面板；可删除 Token 另有一个带完整无障碍名称的删除按钮，不能把按钮嵌套在
  另一个按钮中。删除按钮保持低强调但始终可发现；查询头只能修改，不能删除。
- 点击文字保留原生光标、选区和输入法；点击查询栏空白处聚焦可见的末尾输入，输入隐藏时则聚焦“添加”。
  文本光标不能进入 Token 之间，Token 也不能通过拖拽任意改序；有语义的顺序在对应 Token 内调整。
- 点击“添加”时，可见的末尾文字保持不变。补全面板可使用属于 `EditSession` 的临时搜索或字面值输入；取消
  后临时内容丢弃，焦点和主输入光标回到打开面板前的位置。
- 选择补全项后，新 Token 插入到可见的末尾输入之前，或在输入隐藏时插入到“添加”之前；主输入文字保持不变。
  删除 Token 只删除对应条件，且可撤销。
- Token 作为不可拆分的布局单元换行；可见的末尾输入占满剩余空间。剩余空间不足以正常输入时，输入与“添加”按钮
  一起移到下一行，而不是把输入压缩成一小段。

### 2.4 输入、补全与快捷筛选

- 查询栏只有一个常驻原生输入，仅当当前 `QueryDraft` 接受名称条件时可见。其中的普通文字更新名称条件，并请求当前
  实体范围的名称建议。点击“添加”或在空输入中按 `/` 打开操作补全；`/` 只是快捷键，不是必须学习的语法，也不会劫持
  已有文字中的普通字符。

| 触发方式 | 面板内容 | 选择后的动作 |
|---|---|---|
| 在可见的末尾输入中输入名称 | 当前范围的匹配实体和“查看全部匹配” | 定位实体，或展开同范围的精确列表答案 |
| 点击“添加”或在空输入按 `/` | 当前范围允许的条件、关系和答案动作 | 按需完成“字段 → 运算符 → 值”，再插入 Token |
| 点击 Token 正文 | 该 Token 可修改的片段和合法候选 | 原位替换 Token |

三个上下文复用同一个锚定面板，不展开常驻表单、抽屉或第二种编辑器。

- 候选由当前查询意图、实体类型、字段能力和事实角色共同约束，只显示当前合法的动作，或按规则原子收窄范围后合法的
  类型专属动作；后者必须同时显示目标类型。不能先插入非法片段，再让执行器忽略它。
- 枚举、标签和实体候选在能由现有索引或一次聚合得到时显示当前结果中的精确数量；数量异步计算，不阻塞候选
  出现，尚未得到精确值时不显示估算值。快捷筛选只产生 QueryAction，不保存另一份筛选状态。
- 用于条件、比较或路径端点的实体候选显示名称、类型和消歧所需上下文；选中后绑定稳定 `EntityRef`，不从
  显示文字反向猜测身份。
- 名称建议是当前名称条件的即时预览，不是截断的查询答案。鼠标点击或明确用键盘高亮后按 `Enter` 会定位实体
  并打开详情；选择“查看全部匹配”，或在没有高亮候选时按 `Enter`，会展开精确列表答案。
- 作品、人物和角色的定位会聚焦 Canvas 实体并打开详情。Episode 不进入 Canvas；选中分集建议或结果时，先通过
  `subjectRef` 定位所属作品，再打开“分集”视图并聚焦该条目。所属作品无法解析时保留结果并显示可见错误，不转换为空结果。
- 未完成的字面值保留在局部 EditSession 中并显示诊断；成功解析后才修改查询。粘贴内容只进入当前文本输入，
  不解析为 SQL、Cypher 或任意自然语言查询。
- 中文输入法组合期间不补全、不执行，也不改写输入内容。

### 2.5 鼠标、键盘与焦点

- 名称、字符串、数字和日期使用原生 `<input>`，保留正常光标、选择、复制和粘贴。
- Token 容器是一个语义组，正文按钮用于编辑，可删除 Token 另有相邻删除按钮；文本光标不进入字段名、运算符
  或实体名称内部。聚焦正文后按 `Enter` 编辑，`Delete/Backspace` 删除整个 Token。
- 原生输入获得焦点时，左右键和选择保持浏览器行为；只有空输入位于边界时，左右键才移动到相邻 Token。
- 名称建议默认不高亮；上下键明确选择后，`Enter` 接受候选，否则 `Enter` 查看全部匹配。其他补全只在候选
  已高亮时接受；`Esc` 关闭面板。空输入按一次 `Backspace` 聚焦末尾 Token，再按一次删除；`Cmd/Ctrl+Z`
  撤销最近一次查询修改。
- 新增 Token 后焦点回到可见的末尾输入；输入隐藏时则回到“添加”。修改或取消修改后回到原 Token；删除后依次选择
  相邻 Token、可见的末尾输入或“添加”，不能把焦点留在已经移除的元素上。
- `Tab` 依次经过 Token 内的控件、可见的末尾输入和“添加”按钮，然后离开查询栏，不能形成键盘陷阱。打开或关闭
  补全面板时按触发来源恢复焦点；所有鼠标和触摸操作都有等价键盘路径。

### 2.6 答案与继续探索

名称建议和精确答案承担不同职责，但共享同一个查询栏：建议是短暂的导航层，精确答案是可继续操作的浮层。
答案视图由查询形态决定：列表显示可扫描的行或表格；统计显示分组和指标；集合比较分别显示共同项与两侧差异；
路径按顺序显示每一步实体、事实角色和关系属性。Canvas 显示答案的空间分布，浮层保留精确数量、文本和值。

- 当前已呈现答案中的 Subject、Person 和 Character 直接在 Canvas 高亮；Episode 高亮所属 Subject，事实和路径
  高亮其中可定位的角色实体。统计等没有实体身份的行不制造虚假节点。
- “图上 N 个当前结果”统计当前已呈现答案映射出的唯一节点，不冒充完整结果数；继续显示答案时同步扩充高亮。
- 查询高亮是独立的可点击图层，普通节点适度退后，当前选中节点仍保持最高视觉优先级。查询不自动移动相机；
  点击答案或高亮节点时才定位并打开详情。
- 高亮与图中实体共享缩放语义：远景保持最小可见尺寸，靠近时随节点增长并在上限处停止，缩放过程中保持稳定的
  视觉优先级。

- 合同允许时，点击字段值可添加包含或排除条件，点击列名可排序、分组或统计。
- 点击实体可打开详情，也可创建“查相关实体”“与另一实体比较”或“作为路径端点”等查询动作。
- 合同允许时，点击关系可沿关系前进，或将完整事实角色和属性加入当前条件。
- 所有结果操作都派发与输入、补全相同的 QueryAction，并进入同一撤销历史。

答案浮层展开后，每次有效修改都在短防抖后执行完整查询，新执行取消旧 Worker；名称建议仍可用于快速跳转，
但不覆盖精确答案。执行时只显示轻量状态和“停止”；分页、分批传输和虚拟列表只控制呈现，不改变结果语义。
只有用户添加“最多 N 条”时才限制答案，路径的最大跳数和路径数也必须显示在查询句中。下载、Evidence 和
CoverageSet 不属于默认界面。

### 2.7 视觉、响应式与可访问性

- Token 使用低对比背景和紧凑间距，只在悬停、聚焦或出错时强化边界，避免整页胶囊化。
- 查询栏使用可换行的弹性布局：Token 和“添加”按钮不收缩，可见的末尾输入弹性占宽并保持可用的最小宽度；长 Token
  在自身边界内换行，不能撑出视口。桌面端答案从查询栏下方延伸至视口底部；窄窗口下答案成为有界的底部浮层，
  在查询栏与答案之间保留可操作的 Canvas。
- 补全面板锚定输入、Token 或“添加”按钮，不参与页面流布局；靠近视口边缘时翻转或缩窄，不能遮住触发元素，
  也不能导致查询栏或答案抖动。
- “添加”按钮视觉上可以只显示 `＋`，但必须具有“添加条件、关系或答案”的可访问名称和稳定点击区域。
- 萌元素只用于实体类型图标、空状态和短促反馈，不占用查询空间。
- 焦点、错误和选择不能只靠颜色表达。Token 使用真实按钮或等价语义，补全使用 combobox/listbox 关系；
  查询栏和四种答案视图必须可由键盘和屏幕阅读器完整使用。

## 3. 语义与编辑架构

```text
原生输入 / Token / 结果操作
             │ QueryAction
             ▼
      QueryDraft + history
        │              │
        │ 名称预览     │ 校验与确定性 lowering
        ▼              ▼
  名称候选索引    QueryBundle ──→ Web Worker ──→ QueryResult
        │              ▲                                  │
        └─ 定位实体    └──────── 恢复 / 继续探索 ─────────┘
```

- `QueryDraft` 是唯一可变的查询语义，使用判别联合区分列表、统计、集合比较和路径答案。列表内部再区分实体列表与注册正文命中；
  后者保存正文范围和关键词，返回来源实体或事实、命中字段和片段，不冒充普通实体列表。
- 实体列表的 `EntityScope` 是由
  `subject`、`person`、`character`、`episode` 组成的规范化非空集合，固定按这一顺序编码；默认范围为前三者。
  统计使用单一 `Owner`，不对异构实体做隐式合并。
- 实体列表保存实体范围、名称/范围内正文、条件树、关系、返回列、排序与显式结果数。统计保存单一实体类型、兼容的选择条件、
  分组、指标和统计条件。集合比较保存两侧实体与 Union/Intersect/Except 意图；路径保存起点、终点、遍历策略和
  所有可见边界。
- 多实体列表只执行对当前每种实体都有定义的操作并返回公共列；补全可提供标明目标类型的专属动作。选择该动作时，
  `reducer` 先在同一个 `action` 中收窄 `EntityScope`，再添加片段。多范围 lowering 为兼容的分支，按 `ref`、名称和实体类型的公共答案形状确定性合并；
  不允许一行随实体类型改变结构。
- 每个 Token 都是 `QueryDraft` 的类型化投影，保存稳定键、稳定引用和值；显示文字由查询词汇派生。
- `QueryAction` 是唯一修改入口；历史记录保存成功的 `QueryDraft` 变更，结果操作也派发同一种 action。
- 名称输入直接更新 QueryDraft，并由连续输入合并历史；Token 片段中尚未成功解析的原始值只存在于
  `EditSession`。EditSession 包含目标 Token、片段、原文和诊断，不是第二份查询，解析成功后才派发 action。
- 名称候选由 QueryDraft 的实体范围和名称条件派生。候选请求、当前高亮项和取消句柄属于短暂的
  `SuggestionSession`；它不保存名称、条件或另一份查询。选择候选只派发实体导航动作。
- `QueryDocument` 是类型化、只读的执行算子 DAG；`QueryBundle` 将一个或多个命名查询与答案形状组合起来。
- `AnswerSpec` 描述列表、统计、集合或路径答案的呈现，不附加隐藏筛选；Token 中的字面值可 lowering 为参数值，
  但用户不编辑参数名。
- 集合比较等复合答案可以 lowering 为多个区段，用户不需要看见内部区段和算子。
- 当前 UI 能创建的每种有效 QueryDraft 必须能确定性 lowering，并能从生成的 QueryBundle 无损恢复。
- 当前实体上下文、旧链接迁移和恢复都先生成 QueryDraft，不建立旁路筛选状态。
- 可读文本只用于显示、复制和无障碍描述，不作为执行语言。

### 3.1 界面与状态边界

查询栏使用现有原生 DOM 和微型 store，不使用 `contenteditable`。同一个 `QueryBar` 实例在画布紧凑态和答案
展开态之间切换，不能重建常驻输入；展开、收起和换行都保留焦点、选区与输入法组合状态。不接受名称条件的 `QueryDraft` 只隐藏输入，
不销毁或改作其他控件。输入隐藏时值同步为空，不保存第二份隐藏名称；撤销形态切换会从 `QueryDraft` 恢复原名称。
末尾名称文字属于
`QueryDraft`；补全面板中的临时搜索和字面值属于 `EditSession`。二者都使用原生 `<input>`，但只有前者是
常驻查询入口。Token 使用语义组和可聚焦按钮；组件只接收状态并派发 QueryAction，不能保存自己的查询副本。

QueryDraft 合并并取代当前编辑文档、ExplorerQuery 和配方的可变状态，不在它们之上再增加一层并行 Token AST。
稳定 ID 和类型信息属于 QueryDraft，不需要依赖显示文本或编辑器节点保存。撤销/重做由 QueryDraft 历史
实现；连续输入合并为一次历史操作，选择候选、修改 Token、删除和结果反向操作各形成一个可撤销步骤。

移除 ProseMirror 及当前块级 clause、NodeView 和 `ControlSlot` 表单。不引入 React、Tiptap、CodeMirror 或新的
编辑器框架；本设计既不需要富文本编辑，也不提供可手写查询语法。

### 3.2 查询词汇

| 来源 | 职责 |
|---|---|
| `query-contract.json` | 稳定键、值类型、字段能力、事实角色和合法运算符 |
| 前端领域词汇 | 实体、字段、关系、角色、运算符和动作的首选名称 |
| Release `mappings.json` | 当前数据中的枚举值名称 |

查询栏、补全、Token、结果列和错误信息必须复用这些来源。界面不能显示 `subject.type`、`GTE`、枚举数字或
裸 ID。名称有歧义时显示实体类型和必要上下文，选择后仍只保存稳定引用。

## 4. 数据与查询范围

### 4.1 权威与重建

- Archive 是重新解释上游数据的权威。
- 已验证 Parquet 是 AtlasRelease 的类型化构建输入。
- AtlasRelease 是浏览器读取投影，不成为新的数据权威。

查询字段、索引或物理布局变化时，从同版本 Parquet 重建 AtlasRelease；只有上游投影、schema 或枚举解释
变化时才重新解析 Archive。

公开实体身份为 `subject:<id>`、`person:<id>`、`character:<id>` 和 `episode:<id>`。`fact:<id>` 只在固定
Release 内稳定。完全相同的事实只保存一次，源重复数 `multiplicity` 只用于核验，不作为用户分析维度。

### 4.2 纳入原则

数据只有在能够稳定改变或解释用户答案时才进入查询：

- **Entity**：有稳定身份，可以返回、分享和继续探索；
- **Fact**：表达实体间不可丢失、带角色或属性的事实；
- **Value**：从属于 Entity 或 Fact，没有独立身份。

字段暴露分为 `query`、`evidence` 和 `private`。查询合同分别声明字段是否支持 `lookup`、`fullText`、
`project`、`filter`、`sort`、`group`、`aggregate`、`traverse` 和 `evidence`；补全只展示合同允许的操作。

| 数据 | 用户可查询的范围 |
|---|---|
| Subject | 名称、类型、平台、日期/年份、评分/排名、收藏状态计数、标签、正文、关系和分析 |
| Person | 名称、类型、职业、评论/收藏、正文、参与作品、配音和人物关系 |
| Character | 名称、角色定位、评论/收藏、正文、登场作品、配音和角色关系 |
| Episode | 名称、所属作品、日期/年份、光盘、时长、序号、类型和正文；不进入默认 Canvas 或路径 |
| Fact | 完整角色、可公开属性、存在性、集合、聚合、路径和结果解释 |
| Tag | 按名称筛选，返回名称和源计数；不作为独立实体 |

规范事实保持完整角色：

| FactKind | 角色 | 可查询属性 |
|---|---|---|
| `RELATES_TO` | source/target: Subject | relationType |
| `WORKED_ON` | person: Person, subject: Subject | position |
| `APPEARS_IN` | character: Character, subject: Subject | type |
| `VOICE_CREDIT` | person: Person, character: Character, subjectContext: Subject | type、summaryState、summary 全文 |
| `PERSON_REL` | source/target: Person | relationType、spoiler、ended |
| `CHARACTER_REL` | source/target: Character | relationType、spoiler、ended |

`sortOrder`、`appearEps` 等未注册属性只作证据。`Episode.subjectRef` 支持正向、反向和相关存在性查询。
实体引用和 Release 内的 FactRef 支持直接点查；FactRef 查询必须声明 FactKind 并返回完整角色。

### 4.3 正文、结构值与空值

- 名称、中文名和确定性生成的简繁/日文字形变体用于名称定位，不冒充 infobox 别名。
- 原始日期保留，Subject 与 Episode 的 `year` 是可为空的稳定派生值。
- 枚举通过 Release 映射显示；未知码明确显示为未知值，已知的上游越界哨兵归一为 `null`。
- Subject、Person、Character 的简介、Episode 的分集介绍和 `VOICE_CREDIT.summary` 进入全文查询。
- 原始 infobox 不进入筛选或全文查询，只作详情证据；展示继续使用锁定版本的 Bangumi 官方
  `@bgm38/wiki` 解析器，失败时显示转义原文。
- 全文索引只产生候选，Worker 必须读取权威原文复核；结果返回命中字段、范围和有界片段。
- Tag 保留 `{name, count}`，评分分布保留十个来源票数，不把结构值字符串化。
- 普通比较遇到 `null` 或 `MISSING` 得到 unknown；筛选只保留 true。“为空”和“未提供”保持不同语义。
- 列表量词和空值操作只在查询合同声明支持时出现，不能由编辑器自行推断。
- 名称包含与全文匹配至少需要两个规范化字符；精确实体引用和 FactRef 不受此限制。

## 5. 执行语义

`QueryDocument` 支持 Scan / Values、Lookup / FullText、FactLookup、Filter、MatchFact、FollowRef、Project、
Exists / NotExists、Union / Intersect / Except、Aggregate 和 Path。

- 实体绑定携带实体类型，事实绑定携带 FactKind；不兼容的标量、枚举、日期和实体类型不能隐式转换。
- 算子内部使用 bag；明确去重和集合算子才去重。聚合忽略 `null` 与 `MISSING`；空输入的 count 为 0，
  其他度量为 null。
- 输出顺序固定为 `projection → distinct → orderBy → limit → pagination`。无显式排序时保持稳定输入顺序；
  显式排序并列时使用规范行编码作为最终顺序。
- 默认路径只连接 Subject、Person 和 Character，只遍历合同允许的事实角色对，并保留每一步的 FactRef、角色
  和完整事实上下文。路径不重复实体或 FactRef。
- 规范化和校验覆盖字段能力、类型、事实角色、引用方向、参数和 DAG；同一 Release、规范查询与匹配规则必须
  产生相同 `queryDigest`、结果和值顺序。

主线程只维护编辑、焦点和结果视图；扫描、连接、集合、聚合和路径全部在 Worker 中执行。执行固定一个不可变
Release，协议、查询合同或映射摘要不兼容时停止查询。物理执行应优先使用身份索引、名称/全文候选、投影扫描、
邻接和 Episode 引用目录；无 Range 时允许在缓存预算内读取完整 pack。

查询工作量和结果数没有隐藏配额。需要全局排序、聚合或完整集合时允许读取完整输入，用户通过“停止”取消。
分页只控制传输，虚拟列表只控制 DOM。`QueryResult` 只有完整执行后才标记为 `exact`，不能把候选或已显示批次
冒充完整结果。结果列必须携带字段或事实属性来源，展示层据此选择领域名称，不能根据同名列猜测。

URL 可以保存规范 QueryBundle 和必要视图状态，但不是查询能力或执行上限的依据；超出 URL 容量的查询仍可在
本地完整运行。旧格式只在 URL 边界迁移，新界面不再生成旧语法。

## 6. 实现范围

| 层 | 职责 |
|---|---|
| QueryDraft contract | 定义实体范围、列表、统计、集合比较、路径、条件树和类型化值 |
| Vocabulary | 合并查询合同、领域名称和 Release 枚举，驱动显示与补全 |
| Reducer / history | 用 QueryAction 修改唯一 QueryDraft，并提供合并后的撤销/重做 |
| Query bar | 用同一实例承载画布紧凑态与答案展开态，渲染 Token、按查询形态显隐的末尾输入和添加按钮 |
| Completion / Facet | 在一个锚定面板和临时 EditSession 中完成创建、替换、逻辑分组、值输入和上下文建议 |
| Lowering / lifting | 在 QueryDraft 与 UI 可生成的 QueryBundle 子集间确定性往返 |
| Suggestion session | 从 QueryDraft 派生名称建议，管理高亮、请求和取消，不保存查询语义 |
| Query session | 管理 EditSession、最后有效 Bundle、防抖、取消、恢复和结果提交 |
| Answer views / actions | 在紧凑浮层展示四种精确答案，将当前实体结果映射为 Canvas 高亮，并把结果操作转换为 QueryAction |
| Worker runtime | 复用现有验证、规范化、执行、分页和取消能力 |

实施顺序：

1. 定义 `EntityScope`、实体/注册正文列表变体、`QueryDraft` 判别联合、`QueryAction`、收窄范围规则、历史语义和 lowering/lifting 往返测试。
2. 将跨作品/人物/角色的名称建议接入统一查询栏，实现紧凑/展开布局、按形态显隐输入、Token 与文本共存、共享补全、
   鼠标、触摸、焦点、键盘和
   IME。
3. 接入列表查询的名称、正文、字段、关系、逻辑组、返回、排序、显式结果数、Episode 定位和结果反向操作。
4. 接入统计、集合比较、路径及对应答案视图和上下文动作。
5. 删除独立搜索输入、详细查询切换、ProseMirror、块级 clause/NodeView、`ControlSlot` 表单、旧源码/表单
   转换和重复筛选入口。
6. 使用全量 Release 完成数据、执行、浏览器、容量和 GitHub Pages 验证。

中间阶段只在开发分支验证；只有完整交互和发布门禁通过后的最终产物才部署。

## 7. 验收与发布门禁

### 查询与数据

- 四类实体、全部规范事实、Episode 归属、结构值和注册正文与 Parquet 等价。
- 每个公开字段的类型、能力、运算符和显示名称与查询合同及 Release 映射一致。
- 名称、全文候选、实体/FactRef 点查和 Episode 反向目录可独立重算并通过权威数据复核。
- 三值逻辑、bag/set、排序、分页、聚合、路径和取消语义有独立测试。
- 四种查询形态及每项用户能力都有 Token 创建入口，并能执行、恢复和由结果操作修改。
- 默认实体范围、范围收窄与多范围 lowering 有往返和等价测试，类型专属条件不会暗中丢弃其他类型。

### 交互

- 普通用户不学习语法即可完成名称/正文定位、字段和关系筛选、布尔组合、多列排序、统计、集合比较和路径。
- 全局只有一个查询输入入口；同一查询栏从名称建议渐进扩展到完整答案，不出现“详细查询”切换、块级表单、
  独立源码、重复 Filter Chips 或内部枚举值。
- 默认名称输入同时返回作品、人物和角色建议；“查看全部匹配”使用同一范围，不默认降级为仅查作品。
- 列表或统计中 Token 与末尾文字同时存在时按可见语义共同执行；添加、编辑或删除 Token 不改写文字，
  补全取消后恢复原焦点和光标。
- 全局正文命中、比较和路径不显示无语义的末尾文本输入；查询栏空白处、新增、删除和 `Tab` 的焦点顺序仍完整。
- 选择名称建议只定位实体；“查看全部匹配”和没有高亮候选时的 `Enter` 打开精确答案。建议条数不作为答案
  上限。
- 选择 Episode 建议或结果会定位所属 Subject、打开分集视图并聚焦对应条目；无法解析所属作品时显示错误且
  保留结果。
- 精确答案不接管整页；桌面和窄窗口下 Canvas 都保持可见、可操作。当前已呈现的实体、事实和路径结果按规则
  映射为可点击高亮，继续显示、清空和新答案提交时与浮层原子同步，统计结果不会伪造图节点。
- Token 创建、修改、删除、分组和结果操作共享一份 QueryDraft 历史，不产生第二份查询状态。
- 未完成的值不丢失，诊断定位到对应片段；原生输入不跳光标，结果区不抖动或闪空。
- 点击文字、Token 正文、删除按钮、添加按钮和补全候选分别产生规定动作；中文输入法、复制粘贴、撤销重做、
  触摸、完整键盘操作和屏幕阅读器通过真实浏览器验证。
- 文本光标只出现在名称和字面值输入中；Token 可逐个聚焦、编辑和删除，不依赖任意跨 Token 文本选择。
- 新增、修改、取消和删除 Token 后焦点落点稳定且可预测，不聚焦已移除元素。
- 架构声明支持的桌面浏览器窗口及窄窗口下，可见的末尾输入不足最小可用宽度时整体换到下一行，查询栏、补全和答案
  均可操作且不横向溢出。

### 构建与部署

- 高成本操作只在 Worker 中运行，停止和新查询能立即终止旧 Worker，主线程保持响应。
- 没有隐式结果上限；大结果集通过传输分页和虚拟渲染保持可操作。
- 最终隔离产物通过全量测试、独立数据校验、HTTP smoke、真实浏览器和容量门禁。
- 同一已验证目录作为 GitHub Pages artifact，不从仓库中的中间数据拼装发布。

## 8. 非目标

- 在浏览器运行 LadybugDB、通用数据库或 WASM SQL 引擎；
- 实现完整 SQL、openCypher、任意查询源码或通用图算法平台；
- 用自然语言模型猜测查询含义，或解析任意可读文本为查询；
- 让所有字段支持所有操作，或把 infobox 纳入筛选和全文查询；
- 暴露任意 QueryDocument DAG 的可视化编程界面；
- 维护全局搜索、详细查询、表单、源码、固定模板、Canvas 或结果页各自独立的查询入口或状态；
- 为查询引入富文本、代码编辑器或通用 `contenteditable`；
- 支持写查询、外部调用、用户函数或无界递归。
