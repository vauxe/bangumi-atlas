# GitHub Pages 静态查询设计与实现方案

本文定义 Bangumi 星图的查询产品、语义和实现边界。精确字段、类型与能力以
[`scripts/query-contract.json`](../scripts/query-contract.json) 为准；物理文件以同一 Release 的
manifest 为准。只有第 8 节门禁全部通过后，查询功能才进入可部署产物。

## 1. 目标与原则

用户应当能从作品、人物、角色和分集出发完成：

- 按名称、名称字形变体或正文定位数据；
- 用字段、关系、否定条件和排序缩小结果；
- 查看共同关联、差异和完整关系事实；
- 解释两个实体之间的关系路径；
- 统计、分组，并比较两个实体的关联集合。

查询遵循五条原则：

1. **一个查询**：搜索、条件、关联、统计、路径和集合都是同一份查询文档的组成部分。
2. **领域语言**：用户看到作品、动画、导演、评分等有意义的名称，不看到内部枚举、字段键或 ID。
3. **直接编辑**：用户在同一个编辑面操作可读的查询节点，不设置“表单模式”和“源码模式”。
4. **完整但渐进**：初始界面只显示查找对象和添加入口，全部能力通过按需增加语句块获得。
5. **静态且可取消**：查询只读，在 GitHub Pages 浏览器 Worker 中执行；用户可随时终止执行。

## 2. 查询模型

### 2.1 单一语义链路

```text
ProseMirror EditorState.doc
    │  内联选择、槽位输入、命令和结果操作
    ▼
结构校验与 lowering
    ▼
QueryBundle ──→ Web Worker ──→ QueryResult ──→ 结果视图
    │                  │
    │                  └── AtlasRelease
    └── 区段：QueryDocument + AnswerSpec
```

- `EditorState.doc` 是唯一可变的查询编辑状态，由受 schema 约束的领域节点组成；未完成节点不能执行。
- `QueryDocument` 是类型化、只读的算子 DAG，是单个可执行查询的语义合同。
- `QueryBundle` 包含一个或多个命名区段。比较、集合和全文答案可以由多个区段组成。
- 每个区段由 `QueryDocument` 与 `AnswerSpec` 组成；答案规格只改变展示，不改变查询语义。
- 每次编辑都通过 ProseMirror transaction 修改文档；有效文档确定性降低为规范 `QueryBundle`。
- 参数值也保存在编辑文档的类型化节点中；修改值仍然是 transaction，不建立旁路状态。
- 配方、URL 恢复和上下文动作先转换为编辑文档，再走同一 lowering、校验、规范化和执行链路。

页面只有一份编辑文档和一个最后有效的 `QueryBundle`。实体选择、抽屉开关和 Canvas 相机属于视图
状态，不建立隐藏的筛选或查询状态。未完成的编辑文档保留在原位，但不替换最后一次有效查询。

### 2.2 用户词汇与稳定标识

每个可见查询概念都由同一组查询词汇定义：

| 内容 | 用户看到 | 内部保存 |
|---|---|---|
| 实体类型 | 作品、人物、角色、分集 | owner key |
| 字段 | 类型、年份、评分、收藏数 | field key |
| 关系与角色 | 人物参与、导演、配音 | FactKind、role、枚举值 |
| 运算符 | 等于、不低于、包含、不存在 | operator key |
| 枚举值 | 动画、个人、主角、有内容 | 类型化值 |
| 实体 | 宫崎骏、人物及必要上下文 | 稳定 EntityRef |

静态领域名称集中在前端查询词汇模块；Release 枚举和值名称来自 `mappings.json`。前者随前端版本发布，
后者由 manifest 的映射摘要校验。NodeView、选择器、可读序列化、结果和错误信息复用这两处来源，不能
各自维护同义标签或直接显示内部键。

查询节点只保存稳定键和类型化值，NodeView 始终显示首选领域名称。分享 URL 保存规范
`QueryBundle`，因此显示名称变化不会破坏已分享查询。复制操作提供可读文本，但精确恢复以结构化
文档或分享链接为准，不承诺从任意可读文本还原稳定身份。名称有歧义时，选择器显示实体类型和
必要上下文，选择后绑定稳定引用，不要求用户输入 ID。

错误信息也使用领域语言，例如“作品类型不能使用‘大于’比较”，不能暴露
`subject.type`、`GTE` 或内部枚举数字。

## 3. 数据与能力合同

### 3.1 权威、身份与重建

- Archive 是重新解释上游数据的权威。
- 已验证的 Parquet 是 AtlasRelease 的类型化构建输入。
- AtlasRelease 是浏览器读取投影，不成为新的数据权威。

查询字段、词汇索引或物理布局变化时，从同版本 Parquet 重建 AtlasRelease；只有上游投影、schema
或枚举解释变化时才重新解析 Archive。

公开实体身份为 `subject:<id>`、`person:<id>`、`character:<id>` 和 `episode:<id>`。
`fact:<id>` 只在固定 Release 内稳定。VisualRank、posting、文件偏移、缓存和坐标都是私有实现细节。
完全相同的事实只保存一次，以 `multiplicity` 记录源重复数；它用于来源核验，不作为用户分析维度。

### 3.2 纳入原则

数据能否进入查询取决于它能否回答用户问题：

| 种类 | 判断标准 |
|---|---|
| Entity | 有稳定身份，可返回、分享和继续探索 |
| Fact | 表达实体之间不可丢失、带角色或属性的事实 |
| Value | 从属于 Entity 或 Fact，没有独立身份 |

字段暴露分为：

- `query`：能稳定改变答案，且可类型检查和解释；
- `evidence`：用于解释答案，但不直接参与筛选或排序；
- `private`：只服务存储、加载或执行。

每个字段分别声明 `lookup`、`fullText`、`project`、`filter`、`sort`、`group`、`aggregate`、
`traverse` 和 `evidence` 中实际支持的能力。编辑器只提供合同允许的操作。

| 数据 | 公开用途 |
|---|---|
| Subject | 定位、字段筛选、关系、比较、路径和分析 |
| Person | 定位、职业与热度筛选、参与作品、配音和人物关系 |
| Character | 定位、角色定位与热度筛选、登场作品、配音和角色关系 |
| Episode | 独立定位、筛选、排序、聚合和正文搜索；不进入默认 Canvas 或路径 |
| Fact | 关系约束、返回、集合、路径、聚合和解释 |
| Tag | 按名称筛选并投影名称与源计数 |

规范事实保持完整角色，不把多角色事实拆成无关二元边：

| FactKind | 角色 | 可查询属性 |
|---|---|---|
| `RELATES_TO` | source/target: Subject | relationType |
| `WORKED_ON` | person: Person, subject: Subject | position |
| `APPEARS_IN` | character: Character, subject: Subject | type |
| `VOICE_CREDIT` | person: Person, character: Character, subjectContext: Subject | type、summaryState、summary 全文 |
| `PERSON_REL` | source/target: Person | relationType、spoiler、ended |
| `CHARACTER_REL` | source/target: Character | relationType、spoiler、ended |

`sortOrder`、`appearEps` 等未注册属性只作证据。`Episode.subjectRef` 是 Episode 到 Subject 的
类型化引用，支持正向、反向和相关存在性查询；只有成功解析的引用才能继续遍历。
实体引用和 Release 内的 FactRef 都支持直接点查。FactRef 点查必须声明 FactKind，并返回完整角色，
不能把事实标识当作普通字符串扫描。

### 3.3 结构值、空值与正文

- 原始日期保留；Subject 与 Episode 另外提供稳定派生的 `year`，无法解析时为 `null`。
- 公开枚举字段在查询合同中声明映射命名空间；同一 Release 必须提供作品、人物、角色、分集和事实枚举映射。
- 原始枚举码只用于类型化执行，编辑器和结果通过映射显示领域名称；未知码必须明确显示为未知值。
- 超出官方枚举域的已知上游哨兵规范为 `null`，不能伪装成新的领域枚举值。
- Tag 保留 `{name, count}`；评分分布保留十个来源票数作为证据，不把结构值字符串化。
- 列表条件只使用合同声明的量词；增加量词必须同时扩展合同、编辑器和执行器。
- 普通比较遇到 `null` 或 `MISSING` 得到 unknown，Filter 只保留 true。
- “为空”和“未提供”语义不同；只有保留存在性的字段才能使用“未提供”。
- 上游长文本缺失和 null 已归一为空字符串，因此正文状态只有“有内容”和“无内容”。

名称、中文名以及从两者确定性生成的简繁/日文字形变体用于定位；它们不冒充 Archive infobox 中的
别名。以下长文本进入全文查询：

- Subject、Person、Character 的简介；
- Episode 的分集介绍；
- `VOICE_CREDIT.summary`。

原始 infobox 不进入字段或全文查询，只作证据。浏览器使用 lockfile 固定的 Bangumi 官方
`@bgm38/wiki` 解析器生成只读展示；失败时显示转义后的原文。全文索引只产生候选，Worker 必须
读取权威原文复核。结果只携带命中字段、范围和有界片段，完整原文按需读取。

详细查询的名称包含匹配与全文匹配至少需要两个规范化字符，这与发布的二元字符索引一致；精确实体引用
和 FactRef 不受此限制。该边界由查询合同声明，不能只存在于前端提示或执行器常量中。

## 4. 语义查询文档

### 4.1 结构化可读文档

用户直接编辑结构化查询节点。节点组合后读起来像查询语句，但可见文本不是另一种执行语言。例如：

```text
查找 [作品]
搜索 [简介] 包含 [机器人]
其中 [评分] [不低于] [8]
关联 [人物：宫崎骏]，[参与职位] 是 [导演]
返回 [名称]、[中文名]、[评分]
按 [评分] [从高到低]
限制 [100] 条
```

方括号表示可聚焦的语义槽位，不是实际显示的标点。字段、关系、运算符、枚举和实体是保存稳定键的
原子节点；字面值是类型化可编辑节点。用户通过点击、命令菜单、槽位补全和字面值输入修改它们，
不需要也不允许用自由文本绕过类型和能力合同。

| 语义块 | 能力 |
|---|---|
| 查找、搜索 | 实体扫描、名称定位（含字形变体）、正文检索 |
| 其中 | 类型化比较、集合成员、空值、缺失、嵌套全部/任一/排除 |
| 关联 | 完整事实、命名角色、事实属性、存在或不存在 |
| 返回 | 按需选择结果字段 |
| 统计 | 分组、count/countDistinct/sum/min/max/avg、统计后条件 |
| 排序、限制 | 多列方向、空值顺序和结果上限 |
| 关联比较 | 合并、共同关联和两侧差异 |
| 查找路径 | 最少跳数路径及允许的事实角色对 |
| 参数 | 类型化可复用值，不改变查询结构 |

每项用户能力都必须有对应的语义节点和创建入口。恢复无法无损还原为语义节点的高级 Bundle 时，编辑器
逐项显示其算子和类型化参数并保持可执行；在固定 URL 预算内可无损分享，不要求普通用户直接创建低层算子。
尚未填完的节点以原位占位符和诊断保留，不能静默删除或执行。可读文本序列化只用于复制和无障碍描述，
不作为执行输入。

### 4.2 查询语义

`QueryDocument` 支持 Scan / Values、Lookup / FullText、FactLookup、Filter、MatchFact、FollowRef、Project、
Exists / NotExists、Union / Intersect / Except、Aggregate 和 Path。

实体绑定携带实体类型，事实绑定携带 FactKind。集合可以把不同实体类型的稳定引用合并为通用引用值，
但不能隐式转换不兼容的标量、枚举、日期或实体类型。算子内部使用 bag；明确去重和集合算子才去重。
聚合忽略 `null` 与 `MISSING`；空输入的 count 为 0，其他度量为 null。

输出顺序固定为：

```text
projection → distinct → orderBy → limit → pagination
```

无显式排序时保留输入算子的稳定顺序，使显式限制结果数的查询可以尽早停止；显式排序并列时使用
规范行编码作为最终顺序。分页大小只控制传输，不改变查询含义。

默认路径只连接 Subject、Person 和 Character，并只遍历注册事实的允许角色对。每一步保留起点角色、
FactRef、终点角色和完整事实上下文。路径不重复实体或 FactRef；跳数和路径数是用户可编辑的查询语义，
不受隐藏的执行配额约束。

边界校验覆盖字段能力、类型、事实角色、引用方向、参数和 DAG。规范化删除不可达算子、稳定重命名
内部绑定，并规范化可交换表达式；列表、重复值和非交换顺序保持不变。每个规范查询具有
`queryDigest`，同一 Release、查询和版本化匹配规则必须得到相同的值与顺序。

## 5. 交互设计

### 5.1 一个编辑面

全局搜索框继续负责按名称快速定位，名称匹配包含构建期字形变体；正文搜索属于详细查询。详细查询打开一份
语义查询文档，初始只显示：

```text
查找 [作品]

＋ 添加条件、关联、统计、排序或路径
```

用户不面对预先展开的空表单。点击词语即可原位修改：

- 点击“作品”更换实体类型；
- 点击字段、运算符或值打开与其类型匹配的选择器；
- 输入 `/` 或点击“添加”插入语义块；
- 字段和枚举使用类型匹配的选择器，实体复用星图或全局搜索中的当前选择；
- 字符串、数字和日期直接在类型化值槽位输入；
- `Tab` 在当前语句的可编辑位置间移动；
- `Enter` 完成当前语句，`Cmd/Ctrl + Enter` 执行查询；

所有操作都产生 ProseMirror transaction，共享一份撤销历史。编辑区始终显示同一份可读查询文档，
光标移动不会切换页面或打开另一套编辑器。应用内复制粘贴保留结构，跨应用复制得到可读文本；外部
普通文本只进入当前字面值槽位，不被解析为查询结构。

### 5.2 复杂能力的呈现

- 条件组用缩进表示“全部满足”“任一满足”和“排除”，允许任意合法嵌套。
- 关联块显示关系、目标、方向、命名角色和事实属性；目标复用星图或全局搜索中的当前选择。
- 统计块直接表达度量、分组和统计结果条件，不要求用户理解 `GROUP BY` 或 `HAVING`。
- 多个排序块按文档顺序组成多字段排序；返回字段和结果条数按需出现。
- 关联比较用两个实体生成“全部关联”“共同关联”和两侧差异，内部复用 Union、Intersect 与 Except。
- 路径既可从实体抽屉发起，也可在文档中添加；两种动作生成同一种路径节点。
- 参数在文档中显示有意义的名称，并自动生成类型化值控件；改值不修改查询结构。

结果也是查询入口：点击字段值可以包含或排除该值，列标题可以排序或分组，实体和关系可以继续探索，
选择两个实体可以添加共同关联或路径。所有动作都修改当前语义文档，不建立结果页私有筛选。

### 5.3 反馈、布局与可访问性

编辑立即更新语义文档，只在文档有效时提交执行。连续输入使用短防抖，显式运行立即取消旧执行。
执行期间保留上次结果和容器尺寸，仅更新非侵入式状态；请求返回后一次替换结果，避免编辑区和结果区抖动。

未完成或不合法的节点在原位显示原因和可执行修复，不插入改变整体布局的大块提示。无结果、用户取消、
数据不兼容和网络失败是不同状态。

编辑器必须支持中文输入法、原生选择、复制、撤销、键盘导航和屏幕阅读器。所有内联控件具有可访问名称，
状态不能只依赖颜色。桌面端结果位于编辑区下方或宽屏右侧；窄屏保持单列，弹出选择器不超出视口。

## 6. 静态执行、URL 与结果

主线程维护编辑、URL、焦点和视图状态；扫描、连接、集合、聚合和路径在 Worker 中执行。取消时直接终止
当前 Worker 并重建；新请求也取消旧执行，主线程丢弃不匹配请求的结果。一次执行固定一个不可变 Release；manifest、前端协议、查询
合同或映射摘要不兼容时停止查询，不能混读不同发布。

物理执行遵循：

- 精确身份、名称和全文候选尽早缩小输入；
- 实体引用和 FactRef 使用固定宽度身份索引直接读取；
- 实体扫描按所需字段投影；
- 无显式排序且有显式结果数限制的扫描流式执行并尽早停止；排序、全局聚合和其他需要全局视野的算子完整读取输入；
- 已锚定关系从邻接读取，不做无界笛卡尔积；
- Episode 引用使用正向和反向目录；
- 全文 posting 交集后读取原文复核；
- 无 Range 时使用受缓存预算约束的完整 pack 回退；
- 分页只控制单次传输；结果数和执行工作量没有隐藏配额，响应体与解压尺寸仍按 manifest 校验。

`QueryResult` 只在完整执行后返回 `exact`，不把中间候选冒充结果。结果列携带字段或事实属性的
语义来源，展示层据此使用发布映射显示领域名称，不猜测同名列的含义。Worker 分页与界面逐批显示
相互独立；界面不能把已显示批次冒充完整结果。Evidence 和 CoverageSet
用于验证结果依据与覆盖范围，不作为默认界面功能。

新链接只写规范 `qb` 参数，并附带必要的相机和选择状态。满足 URL 字节上限的 QueryBundle 可无损分享；
超限查询仍在本地执行，只是不写入 `qb`。浏览器前进与后退恢复可分享的查询和选择。旧查询参数只在 URL
边界迁移，页面不再生成旧格式；不存在的固定 Release 不会静默切换到最新版本。

## 7. 实现方案

### 7.1 分层

| 层 | 职责 |
|---|---|
| Query vocabulary | 合并静态领域名称、合同和发布映射，提供首选名称、类型与稳定键 |
| Query schema | 定义查询节点、合法嵌套、节点属性和未完成状态 |
| NodeView | 用领域名称渲染节点，并提供类型化内联编辑入口 |
| Commands / plugins | 处理添加、修改、删除、补全、键盘、历史和结果反向操作 |
| Lowering / serialization | 在编辑文档与 `QueryBundle` 间确定性转换，并生成可读复制文本 |
| Query session | 管理编辑状态、最后有效 Bundle、取消、URL 和结果提交 |
| Worker runtime | 复用现有规范化、验证、执行、分页和取消能力 |

编辑器直接使用 ProseMirror 核心包，不引入 React、Tiptap、CodeMirror 或通用富文本 StarterKit。
查询需要的是受 schema 约束的结构、事务、选择和 NodeView，而不是以文本为权威的代码编辑器或通用
富文本抽象。ProseMirror 文档是唯一可变的查询编辑状态；NodeView 和外部控件只能 dispatch
transaction，不能另存查询草稿。

Schema 约束文档结构，查询合同继续负责字段能力、值类型、事实角色和执行边界。节点属性保存稳定键，
显示名称由词汇注册表派生。有效编辑文档 lowering 为 `QueryBundle`；URL、配方和旧查询恢复时，
先转换为编辑文档。可读序列化不参与执行，也不承担稳定身份。

查询合同定义稳定键、类型和能力；静态领域名称由前端查询词汇覆盖，Release 枚举由映射数据提供。
构建与测试分别检查公开概念和映射命名空间完整，任何普通用户路径都不能回退显示内部键。

现有英文 Atlas Query 只作为旧链接迁移输入：先解析为 `QueryDocument`，再转换为编辑文档。新界面、
URL 和配方不再生成它；删除旧表单、源码 textarea、参数 JSON 输入，以及旧语法与表单之间的双向转换。

### 7.2 实施顺序

1. **词汇合同**：统一实体、字段、事实、角色、运算符和 Release 枚举的显示来源及完整性验证。
2. **结构核心**：定义 ProseMirror schema、结构序列化和 lowering；用结构往返测试覆盖全部 QueryDocument 算子。
3. **基础编辑**：实现查找、搜索、条件、关联、返回、排序和限制的 NodeView、命令及键盘交互。
4. **完整能力**：补齐嵌套逻辑、事实属性、多关联、多排序、统计、集合、路径和参数。
5. **入口统一**：将搜索、抽屉、Canvas、结果操作、配方和 URL 全部接入语义文档事务，移除旧查询 UI。
6. **发布集成**：按合同变化重建必要静态数据，执行全量数据、单元、浏览器、容量和 Pages 验证。

中间阶段只在开发分支验证，不进入 Pages 产物。每一步先完成可执行语义与结构往返测试，再增加对应 UI；
不能先做看似可用但无法无损保存、恢复，或在固定 URL 预算内分享的控件。

## 8. 验收与发布门禁

### 8.1 查询与数据

- 四类实体、全部规范事实、Episode 归属、结构值和已注册正文与 Parquet 等价；
- 实体引用和 FactRef 点查返回正确类型、完整角色与稳定身份；
- 字段注册表、查询合同、Release 映射和 manifest 一致；
- 每个公开概念都有有意义的首选名称，用户界面和错误信息不泄漏内部键或枚举值；
- 类型、三值逻辑、bag/set、排序、分页、聚合和路径语义通过独立测试；
- 每项用户能力都能创建、执行并恢复，在固定 URL 预算内可结构化分享；高级 Bundle 的全部算子可结构化显示并恢复；
- 名称、全文候选、FactRef 和 Episode 反向目录可独立重算。

### 8.2 交互

- 普通用户无需语法知识即可完成名称/正文定位、字段和关系筛选、多列排序与结果定位；
- 槽位输入、内联选择、命令和结果操作共享一份 transaction 历史且不产生第二份查询状态；
- 嵌套条件、事实属性、统计、集合、路径和参数都有可发现入口；
- 未完成节点不会丢失，诊断定位到对应节点，全部合法能力都有结构化表示；
- 中文输入、复制粘贴、撤销重做、键盘和屏幕阅读器交互通过真实浏览器验证；
- 连续修改查询时编辑器不跳光标，结果容器不清空或改变位置。

### 8.3 构建与部署

- 高成本算子只在 Worker 中运行，取消能立即终止当前 Worker；
- 最终隔离产物通过全量测试、独立数据校验、HTTP smoke、真实浏览器和容量门禁；
- 同一已验证目录作为 GitHub Pages artifact，不从仓库中的中间数据拼装发布。

## 9. 非目标

- 在浏览器运行 LadybugDB 或通用数据库；
- 实现完整 SQL、openCypher 或任意图算法平台；
- 让所有字段支持所有算子；
- 把可读复制文本、自由自然语言或概率模型作为查询执行输入；
- 维护独立源码编辑器或完整的用户查询语法；
- 支持写查询、外部调用、用户函数或无界递归；
- 为 Canvas、结果、模板、旧语法或迁移格式维护另一套执行器。
