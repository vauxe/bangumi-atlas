# GitHub Pages 静态结构化查询设计

本文定义 Bangumi 星图的查询产品、交互和实现边界。字段、类型与能力以
[`scripts/query-contract.json`](../scripts/query-contract.json) 为准；物理产物以同一 Release 的
`manifest.json` 为准。最终站点必须是可部署到 GitHub Pages 的纯静态产物。

## 1. 产品模型

查询服务于一个核心任务：**从作品、人物、角色或分集中找到一组符合条件的条目，并继续理解它们**。

| 语义 | 示例 |
|---|---|
| 范围 | 作品、人物、角色、分集，可多选 |
| 名称 | 名称包含“机器人” |
| 属性 | 评分不低于 8、年份为 2024、标签包含科幻 |
| 关联 | 有宫崎骏参与、没有某个角色登场 |
| 正文 | 简介或分集介绍包含“时间旅行” |
| 逻辑 | 全部满足、任一满足、排除 |
| 顺序 | 按评分降序，只看前 10 条 |

查询只有一个用户入口：**统一查询栏**。名称、范围和结构化条件共同投影自一份 `QueryDraft`，不再区分搜索、
筛选、详细查询或手写语句。用户不需要学习 SQL、Cypher、字段键或枚举码。

聚合、集合运算和路径仍是 `QueryDocument` 的执行能力，但不进入默认查询栏。它们不应迫使普通用户先选择
“答案形态”，也不应增加主流程的控件和概念。

设计原则：

1. **先表达目标，再补充约束**：默认可直接输入名称，复杂度随用户动作出现。
2. **字段优先**：添加时直接找“评分、年份、标签、关联、正文、排序”，不先选技术类别或实体层级。
3. **一种状态**：输入、Token、恢复、执行和结果操作都修改同一份查询。
4. **领域语言**：只显示用户能理解的名称，不显示内部键、枚举码和稳定 ID。
5. **显式执行**：编辑不会自动运行完整查询；用户点击查询，运行中同一按钮变为停止。
6. **结果留在语境中**：Canvas 保持可见，结果用于高亮、打开详情和继续筛选。

## 2. 交互模型

### 2.1 统一查询栏

查询栏位于 Canvas 左上方，由范围 Token、条件 Token、名称输入、添加按钮和查询按钮组成：

```text
[作品、人物、角色]  机器人▏                           ＋  🔍

[作品]  [评分 ≥ 8]  [导演是宫崎骏]  机器人▏          ＋  🔍
```

- 范围 Token 直接列出当前实体类型；四类全选时才简写为 `[全部类型]`，不使用含义不明的“全部”。
- 点击范围后可独立勾选作品、人物、角色和分集，至少保留一种。每次勾选立即修改 QueryDraft，但不执行查询。
- 与已有条件不兼容的类型不可加入；界面保留当前条件并说明冲突，不隐式清空或改写查询。
- 名称输入始终是原生 `<input>`，保留光标、选区、粘贴和输入法行为。
- 一个 Token 表达一个完整条件，例如 `[评分 ≥ 8]`，而不是三个相邻控件。
- Token 正文用于编辑；删除是相邻的独立按钮。删除只移除对应语义，并可撤销。
- 名称文字与 Token 同时生效；添加、修改或删除 Token 不改写名称文字。
- 空名称输入中按 `/` 与点击“添加”等价；它只是快捷键，不是查询语法。

布局以 CSS 可用空间为准，不按 2K、4K 等硬件分辨率分叉。详情打开时，查询区、图例和抽屉共享可用宽度，不能
相互遮挡。空间变窄时 Token 整体换行，名称输入和查询动作始终可用；添加器按内容宽度排布并独立滚动。结果在
可读宽度保留表格，只有自身容器不足时才转换为卡片。

### 2.2 字段优先的添加器

点击“添加”直接展示当前查询可以添加的全部用户条件，不重复名称输入已经覆盖的原名和中文名：

```text
评分        年份        播出日期      是否有简介
作品类型    人物类型    评论数        收藏数
用户标签    职业        角色定位      简介 / 分集介绍
按关联筛选  排序
```

添加器是一个扁平列表，不按底层实体或功能再次分组。含义和值域相同的字段只出现一次；同名但值域不同的字段
始终使用“作品类型 / 人物类型”这类稳定名称消歧，不随当前范围改名。字段只适用于部分当前实体时，用紧凑副标签
预告范围变化，例如“评论数 · 仅人物、角色”或“评分 · 仅作品”。
高频字段排在前面，但不隐藏其余用户条件，也不提供搜索或“查看更多”入口；面板本身可滚动。合同中的原名、中文名
仍能恢复和编辑旧查询，新查询统一由名称输入完成定位，避免同一种意图出现两个入口。
选择字段后，同一面板显示只读字段 Token、运算符和值，并直接聚焦待填写的值，不再显示第二个字段选择器；
返回字段列表统一使用标题栏返回按钮。枚举、标签和实体引用提供可读候选，用户不输入值码或 ID。排序只有一个
入口，以“先按 / 再按”表达优先级；共同字段直接显示，专属字段显示为“作品 · 评分”。排序始终保留当前实体范围；不适用该字段的实体
视为缺少排序值并排在后面，不会借排序暗中筛掉实体。

值控件由值域决定：布尔值、平台、职业等小型封闭值域显示完整列表；标签输入后匹配完整发布词表；实体引用按
完整结果连续分页。大型候选集只分批传输和渲染，不截断可选值。数值使用数字输入，日期使用日期输入，开放文本
使用文本输入。数值条件直接显示六种比较；可空字段再显示“为空 / 不为空”。数值集合由“任一满足”的等值条件
表达，不作为新条件选项；底层仍保留集合运算，并原样恢复旧查询。

关系输入聚焦和继续输入都使用当前 Release 的完整关系词表；列表按需渲染，输入用于缩小范围，不是访问冷门关系
的前置条件。候选列表不能遮蔽对象和应用动作。

选择只适用于部分实体的字段时，一次可撤销修改先把范围收窄到所有兼容实体，再添加条件；不能让执行器暗中
丢弃其他类型。与现有条件冲突的范围不可选，并给出对应条件的可读说明。

添加器不提供“属性 / 关联 / 正文 / 排序”的第一层类别选择，不提供“统计 / 比较 / 路径”模式，也不设置
“其他操作”菜单。关系、正文和排序与字段一起出现在同一个平面中。
关联筛选只提供一个入口。选择关系使用面板内的独立全宽页面：搜索框下直接显示当前 Release 的全部具体关系及
两端实体，列表占用主要可用高度并自行滚动，不使用浮动下拉框；输入只缩小列表，不是访问冷门关系的前置条件。
选择关系后再填写关联对象和少量可读属性，应用时与关系条件一起原子收窄范围。
简介条件只输入关键词；作品、人物和角色自动搜索简介，分集自动搜索分集介绍，不再选择底层正文范围。
“所有正文与关系备注”是独立的全库正文查询，不作为普通条件的范围选项。

单条条件不显示布尔组。用户加入多个条件后，才提供“全部满足 / 任一满足”；排除由“不等于”“不属于”或
“没有关联”等具体条件表达。恢复旧查询中的嵌套排除组时保持其语义，但不把排除伪装成会重组条件的并列模式。

### 2.3 名称建议与完整查询

输入名称时只请求当前范围的轻量建议。建议用于快速定位实体，不是被截断的查询结果；选择建议会打开对应实体，
Episode 则定位所属 Subject 并打开分集。

完整查询只由查询按钮启动。运行时：

- 查询按钮变为停止按钮，并具有明确的忙碌状态；
- Worker 执行扫描、关系匹配、排序和分页，主线程保持响应；
- 修改查询只更新可见 QueryDraft，不偷偷开始下一次执行；保留的旧结果标为“上次结果”；
- 新结果完整提交前保留上一次有效结果，取消不会提交半成品；
- 只有显式“前 N 条”会限制语义结果，分页和虚拟列表只限制传输与渲染。

### 2.4 结果与 Canvas

精确结果在查询栏下方的有界工作区显示，Canvas 始终可见并可交互。关闭工作区只收起结果，不清空查询、图上高亮
或撤销历史，也不停止正在执行的查询。运行中修改条件会使旧执行失效，主动停止则使用查询按钮。收起后保留明确的“查看结果”入口。

- 当前已呈现的 Subject、Person 和 Character 在独立图层高亮；Episode 高亮所属 Subject。
- 高亮节点保持可点击，普通节点适度退后，当前选中节点仍具有最高视觉优先级。
- 查询不自动移动相机；点击结果或高亮节点时才定位并打开详情。
- 远景高亮保持最小可见尺寸，靠近时按节点尺度增长并设置上限，避免缩放后突然消失。
- 结果显示中文名和原名；枚举、关系角色和空值使用领域语言，不显示裸 ID。

### 2.5 焦点、键盘与可访问性

- 打开添加器后焦点进入第一个条件；选择字段后进入待填写值；关闭时回到触发按钮。
- 名称建议默认不高亮；上下键选择，`Enter` 接受已选候选，`Esc` 关闭面板。
- Token 聚焦后按 `Enter` 编辑，`Delete/Backspace` 删除；删除后聚焦最近的剩余 Token 或名称输入。
- `Cmd/Ctrl+Z` 与 `Cmd/Ctrl+Shift+Z` 撤销和重做查询动作。
- `Tab` 可依次经过所有可见控件并离开查询栏，不形成键盘陷阱。
- 焦点、错误、选中和运行状态不能只靠颜色表达；图标按钮必须有稳定的中文可访问名称和点击区域。
- 萌元素只用于品牌、实体类型和短促反馈，不挤占查询内容。

## 3. 语义与状态

```text
名称输入 / Token / 结果操作
            │ QueryAction
            ▼
     QueryDraft + history
       │              │
       │ 名称建议     │ 校验与 lowering
       ▼              ▼
  轻量名称索引   QueryBundle ──→ Web Worker ──→ QueryResult
```

- `QueryDraft` 是唯一可变查询，分别保存可同时生效的名称与正文、实体范围、条件树、关系、返回列、排序和显式前 N 条。
- `EntityScope` 由 `subject`、`person`、`character`、`episode` 组成，默认范围为前三者，编码顺序固定。
- 多实体查询 lowering 为兼容分支，再按 `ref`、名称和实体类型合并成稳定公共结果形状。
- 每个 Token 都是 QueryDraft 的类型化投影；显示文字由领域词汇生成，不能反向解析为查询。
- `QueryAction` 是唯一修改入口。连续名称输入合并历史，添加、替换、删除和范围收窄各形成可撤销动作。
- 未完成的字面值、候选高亮和取消句柄只属于临时 `EditSession` / `SuggestionSession`，不是第二份查询。
- `QueryDocument` 是类型化、只读的执行 DAG；`QueryBundle` 组合命名查询与答案描述。UI 只生成其稳定子集。
- 当前实体上下文、URL 恢复和旧链接迁移都先生成 QueryDraft，不建立旁路筛选状态。

查询栏使用原生 DOM 和微型 store，不使用 `contenteditable`，也不引入 ProseMirror、Tiptap、CodeMirror 或组件框架。
本设计需要离散 Token 与原生输入，不需要富文本编辑或可手写查询源码。

### 3.1 查询词汇

| 来源 | 职责 |
|---|---|
| `query-contract.json` | 稳定键、值类型、字段能力、事实角色和合法运算符 |
| 前端领域词汇 | 实体、字段、关系、角色、运算符和动作的首选名称 |
| Release `mappings.json` | 当前数据中的枚举值名称 |

查询栏、候选、Token、结果列和错误信息复用这些来源。界面不能显示 `subject.type`、`GTE`、枚举数字或裸 ID；
名称有歧义时显示实体类型和必要上下文，内部仍保存稳定引用。

## 4. 数据与查询范围

### 4.1 权威与重建

- Archive 是重新解释上游数据的权威。
- 已验证 Parquet 是 AtlasRelease 的类型化构建输入。
- AtlasRelease 是浏览器读取投影，不成为新的数据权威。

源字段、索引或物理布局变化时，从同版本 Parquet 重建 AtlasRelease；完全由现有结构字段确定的派生查询字段可复用
内容寻址数据文件，但必须重新生成并验证查询合同摘要和 manifest。只有上游投影、schema 或枚举解释变化时才重新
解析 Archive。

公开实体身份为 `subject:<id>`、`person:<id>`、`character:<id>` 和 `episode:<id>`。`fact:<id>` 只在固定
Release 内稳定。完全相同的事实只保存一次，源重复数 `multiplicity` 只用于核验，不作为用户分析维度。

### 4.2 纳入原则

数据只有在能够稳定改变或解释用户答案时才进入查询：

- **Entity**：有稳定身份，可以返回、分享和继续探索；
- **Fact**：表达实体间不可丢失、带角色或属性的事实；
- **Value**：从属于 Entity 或 Fact，没有独立身份。

字段暴露分为 `query`、`evidence` 和 `private`。查询合同分别声明字段是否支持 `lookup`、`fullText`、
`project`、`filter`、`sort`、`group`、`aggregate`、`traverse` 和 `evidence`；界面只展示合同允许的操作。

| 数据 | 用户可查询的范围 |
|---|---|
| Subject | 名称、类型、平台、日期/年份、评分/评分人数/排名、收藏状态计数/总收藏数、标签、正文和关系 |
| Person | 名称、类型、职业、评论/收藏、正文、参与作品、配音和人物关系 |
| Character | 名称、角色定位、评论/收藏、正文、登场作品、配音和角色关系 |
| Episode | 名称、所属作品、日期/年份、光盘、时长、序号、类型和正文；不进入默认 Canvas |
| Fact | 完整角色、可公开属性、存在性和结果解释 |
| Tag | 按名称筛选，返回名称和源计数；不作为独立实体 |

规范事实保持完整角色：

| FactKind | 角色 | 可查询属性 |
|---|---|---|
| `RELATES_TO` | source/target: Subject | relationType |
| `WORKED_ON` | person: Person, subject: Subject | position |
| `APPEARS_IN` | character: Character, subject: Subject | type |
| `VOICE_CREDIT` | person: Person, character: Character, subjectContext: Subject | type、summaryState、summary 全文 |
| `PERSON_REL` | source/target: Person | relationType、spoiler、ended |
| `CHARACTER_REL` | source/target: Character | relationType、spoiler、ended |

`sortOrder`、`appearEps` 等未注册属性只作证据。`Episode.subjectRef` 支持正向、反向和相关存在性查询。
实体引用和 Release 内的 FactRef 支持直接点查；FactRef 查询必须声明 FactKind 并返回完整角色。
三元 `VOICE_CREDIT` 的人物、角色和作品限定必须落在同一条事实上；不能用两个独立存在性条件近似，否则可能命中
两条不同的配音记录。

### 4.3 正文、结构值与空值

- 名称、中文名和确定性生成的简繁/日文字形变体用于名称定位，不冒充 infobox 别名。
- 原始日期保留，Subject 与 Episode 的 `year` 是可为空的稳定派生值。
- 枚举通过 Release 映射显示；未知码明确显示为未知值，已知的上游越界哨兵归一为 `null`。
- Subject、Person、Character 的简介、Episode 的分集介绍和 `VOICE_CREDIT.summary` 进入全文查询。
- 原始 infobox 不进入筛选或全文查询，只作详情证据；展示使用锁定版本的 Bangumi 官方 `@bgm38/wiki` 解析器，
  失败时显示转义原文。
- 全文索引只产生候选，Worker 必须读取权威原文复核；结果返回命中字段、范围和有界片段。
- Tag 保留 `{name, count}`，评分分布保留十个来源票数，不把结构值字符串化。
- 普通比较遇到 `null` 或 `MISSING` 得到 unknown；筛选只保留 true。“为空”和“未提供”保持不同语义。
- 名称包含与全文匹配至少需要两个规范化字符；精确实体引用和 FactRef 不受此限制。

## 5. 执行语义

`QueryDocument` 支持 Scan / Values、Lookup / FullText、FactLookup、Filter、MatchFact、FollowRef、Project、
Exists / NotExists、Union / Intersect / Except、Aggregate 和 Path。

- 实体绑定携带实体类型，事实绑定携带 FactKind；不兼容的标量、枚举、日期和实体类型不能隐式转换。
- 算子内部使用 bag；明确去重和集合算子才去重。聚合忽略 `null` 与 `MISSING`；空输入的 count 为 0，
  其他度量为 null。
- 输出顺序固定为 `projection → distinct → orderBy → limit → pagination`。无显式排序时保持稳定输入顺序；
  显式排序并列时使用规范行编码作为最终顺序。
- 排序键不在返回列中时，编译器把它加入仅供执行的内部投影；专属排序键在其他实体分支中为空并排在后面。
  内部排序列参与校验和排序，但不会进入结果行、证据或去重身份。
- 路径只遍历合同允许的事实角色对，并保留每一步 FactRef、角色和完整事实上下文。
- 规范化和校验覆盖字段能力、类型、事实角色、引用方向、参数和 DAG；同一 Release、规范查询与匹配规则必须
  产生相同 `queryDigest`、结果和值顺序。

主线程只维护编辑、焦点和结果视图；扫描、连接、集合、聚合和路径在 Worker 中执行。执行固定一个不可变
Release，协议、查询合同或映射摘要不兼容时停止查询。物理执行优先使用身份索引、名称/全文候选、投影扫描、
邻接和 Episode 引用目录；无 Range 时允许在缓存预算内读取完整 pack。

查询工作量和结果数没有隐藏配额。需要全局排序、聚合或完整集合时允许读取完整输入，用户通过“停止”取消。
分页只控制传输，虚拟列表只控制 DOM。`QueryResult` 只有完整执行后才标记为 `exact`，不能把候选或已显示批次
冒充完整结果。结果列携带字段或事实属性来源，展示层据此选择领域名称。

URL 可以保存规范 QueryBundle 和必要视图状态，但不是查询能力或执行上限的依据；超出 URL 容量的查询仍可在
本地完整运行。旧格式只在 URL 边界迁移，新界面不再生成旧语法。

## 6. 模块边界

| 层 | 职责 |
|---|---|
| QueryDraft contract | 定义实体范围、名称/正文、条件树、关系、返回和排序 |
| Vocabulary | 合并查询合同、领域名称和 Release 枚举，驱动显示与候选 |
| Reducer / history | 用 QueryAction 修改唯一 QueryDraft，并提供撤销/重做 |
| Query bar | 渲染范围、Token、名称输入、添加和查询/停止按钮 |
| Add picker / editor | 完整展示合法字段，在临时 EditSession 中完成值输入和逻辑分组 |
| Lowering / lifting | 在 QueryDraft 与 UI 可生成的 QueryBundle 子集间确定性往返 |
| Query session | 管理最后有效结果、显式执行、取消、恢复和结果提交 |
| Answer view | 显示精确列表，将实体结果映射为 Canvas 高亮 |
| Worker runtime | 验证、规范化、执行、分页和取消 |

底层聚合、集合和路径模块保持独立，不向默认查询栏泄漏执行模型。最终产物通过完整门禁后再部署，不发布中间阶段。

## 7. 验收与发布门禁

### 查询与数据

- 四类实体、全部规范事实、Episode 归属、结构值和注册正文与 Parquet 等价。
- Subject 的评分人数和总收藏数由既有评分分布与五种收藏状态确定性派生，不增加发布数据副本。
- 每个公开字段的类型、能力、运算符和显示名称与查询合同及 Release 映射一致。
- 名称、全文候选、实体/FactRef 点查和 Episode 反向目录可独立重算并通过权威数据复核。
- 三值逻辑、bag/set、排序、分页、聚合、路径和取消语义有独立测试。
- 默认实体范围、范围收窄与多范围 lowering 有往返和等价测试；类型专属条件显式收窄范围，类型专属排序保留
  其他类型并把无值结果排在后面。

### 交互

- 普通用户不学习语法即可完成名称/正文定位、字段和关系筛选、布尔组合、多列排序与前 N 条。
- Episode 所属作品通过名称选择；三元配音关系可在同一条件中同时限定人物、角色和作品。
- 全局只有一个查询入口，不出现详细查询切换、答案模式、块级表单、独立源码或重复筛选状态。
- 点击范围只修改范围；添加器完整展示当前合法的字段和功能，高频字段靠前但不隐藏其他字段。
- 默认名称输入同时返回作品、人物和角色建议；建议数量不作为精确答案上限。
- 修改查询不会自动执行；查询/停止状态明确，取消不提交半成品。
- Episode 结果定位所属 Subject 并打开分集；无法解析时保留结果并显示错误。
- 精确结果不接管整页；Canvas 保持可见，当前已呈现实体映射为可点击高亮。
- Token 创建、修改、删除和分组共享一份 QueryDraft 历史，不产生第二份查询状态。
- 中文输入法、复制粘贴、撤销重做、鼠标、完整键盘和屏幕阅读器通过真实浏览器验证。
- 支持的桌面窗口及浏览器缩放后的等效窄视口中，查询栏、添加器、结果和详情互不遮挡，均可操作且不横向溢出。

### 构建与部署

- 高成本操作只在 Worker 中运行，停止能立即终止旧 Worker，主线程保持响应。
- 没有隐式结果上限；大结果集通过传输分页和虚拟渲染保持可操作。
- 最终隔离产物通过全量测试、独立数据校验、HTTP smoke、真实浏览器和容量门禁。
- 同一已验证目录作为 GitHub Pages artifact，不从中间数据拼装发布。

## 8. 非目标

- 在浏览器运行 LadybugDB、通用数据库或 WASM SQL 引擎；
- 实现完整 SQL、openCypher、任意查询源码或通用图算法控制台；
- 用自然语言模型猜测查询含义，或解析任意可读文本为查询；
- 让所有字段支持所有操作，或把 infobox 纳入筛选和全文查询；
- 在默认查询栏暴露聚合、集合比较、路径或任意 QueryDocument DAG；
- 维护全局搜索、详细查询、表单、源码、固定模板或结果页各自独立的查询状态；
- 为查询引入富文本、代码编辑器或通用 `contenteditable`；
- 支持写查询、外部调用、用户函数或无界递归。
